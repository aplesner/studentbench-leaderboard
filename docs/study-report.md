# Model-ranking report

`studentbench_leaderboard.study_report.render_report(study_dir)` creates a self-contained `report.html` from local analysis artifacts, frozen judge configurations, and saved request snapshots. It does not call models, load the raw SSOT, choose a judge, or advance the validation/test state. Rendering preserves the analyses and model responses byte for byte.

```python
from pathlib import Path
from studentbench_leaderboard.study_report import render_report

render_report(Path("results/ranking-study-20260910"))
```

The report follows an experimental narrative: the question and principal results; students, plan pairs, and generator systems; the model/effort/response screen; input refinement and selection; held-out results; exploratory provider and example comparisons; focused panel follow-up; sensitivity checks; human consistency and density; explanation/context audits; exact prompts and reproducibility. Each experiment has a purpose paragraph and separately captioned result tables. Earlier development results and secondary sensitivity tables are collapsed. The main sensitivity display is limited to the selected judge on the reviewed and dense test schedules.

The ranked entities are **lesson-plan generator systems**, meaning model identity plus generation settings. They are distinct from the judge models. All plans for a student belong to one split. A student can supply several plan pairs, so the student counts and pair counts are explained separately. The report gives both the average number of plan comparisons per generator matchup and the uneven observed matchup distribution. It does not confuse the 66 possible generator matchups with the 155 or 293 lesson-plan pairs.

Friendly judge labels appear in headings, selectors, legends, and result tables. Technical variant IDs, exact model IDs, version hashes, request settings, and response schemas remain available in inspectable configuration details. The original four-model panels contain Luna, Terra, Sol, and Astra, all at either low or high reasoning. Original prompts were zero-shot: no human lesson-plan verdicts or demonstrations were supplied. Pretest correct answers are task context, not calibration examples.

The selected-judge description explains reproducible A/B shuffling, citing evidence before choosing a winner, and removing hidden archival answer fields in plain language. The opening results define Kendall τ-b, Spearman ρ, generator-order agreement, and average rank-position error. A high overall correlation does not imply a certain winner; the test human winner’s rank uncertainty and the human/AI point-winner mismatch remain visible.

The Overall leaderboard tab combines the quality families. Each other tab recomputes both rankings using only that rubric family: the Difficulty tab, for example, compares difficulty-specific generator rankings. It does not filter the overall ranking’s rows. Density curves continue to use the overall rubric composite. Answer coverage means usable rubric comparisons divided by requested rubric comparisons, distinct from the fraction of plan pairs with any answer. Explicit ties count as answers; insufficient evidence and missing responses do not.

Every generated table supports text and numeric column sorting through keyboard-accessible header buttons. Column headers have `scope="col"` and `aria-sort`; first cells are row headers. Sort status is announced through a live region. Currency, percentages, negative values, and comma-separated counts sort numerically; unavailable values stay last in either direction. Ties preserve the original row order. Each table has a reset button that restores its original order, including the paired model/effort display. Sorting changes only the displayed DOM, not the embedded data or numerical analyses.

The model/effort screen compares eight evidence-and-winner variants on the same 60 pairs. Response-design controls hold model and reasoning fixed within each contrast. The input comparison requires matching pair identities and job fingerprints, not just matching counts. It never substitutes the 120-pair refinement results into the 60-pair input comparison. Restored text, archival-field removal, and template revisions are one bundle whose component effects are not separately identified. Optional offline paired effort contrasts show student-resampling uncertainty; they do not imply that higher reasoning is generally better or worse.

Statistical sensitivity checks use concrete examples. A student with four plans supplies six pairs while a student with two plans supplies one; equal-student weighting equalizes their total influence and rescales weights to preserve each fit’s original total pair weight. Changing the human reference can change agreement without changing an AI answer, for example when unanswered difficult questions are also removed from the human ranking. Whole-split references include all available reviewed criterion variants. Removing answer accuracy or strategies/formats changes the quality definition for both human and AI rankings. These checks do not retune a judge.

The renderer reads `manifest.json`, `variants.json`, `analysis.json`, `selection.json`, completed round analyses, human/audit summaries, and context coverage/provenance. Preview filenames are not treated as completed experiments. Missing analyses remain pending. Partial results retain their scheduled denominator and show missing calls. Unavailable models and panels requiring them have no inferred quality score. Terminal request failures remain missing outcomes, with no fabricated ties; the report notes when output-cap exhaustion makes random-missingness assumptions inappropriate.

`report_extension.json` can point to two sibling studies: `study_dir` supplies the original provider/example extension, and `followup_study_dir` supplies the focused follow-up. Each sibling uses its own `report_metadata.json`, analysis files, variants/configurations, saved calls, summary, paired deltas, and exports. The embedded objects are `D.extension` and `D.followup`; catalog keys use `extension:` and `followup:` prefixes. Identical imported variant names therefore retain independent provenance and accounting. Both follow-ups are explicitly exploratory validation after test exposure, and neither replaces the original frozen selection or its held-out results.

The optional `revision_statistics_file` pointer loads an offline explanatory audit. It can supply exact split/schedule counts, generator-matchup distributions, paired low/high effort contrasts, and reconstruction of the example interval. A sibling `human_comparator.json`, when present, supplies a matched-reference human diagnostic. These pointers must remain inside the containing results directory. Reproducibility links include each study’s analyses, summaries, verification, source snapshots, CSVs, and execution ledgers. Absent artifacts and symlinks escaping the validated root are excluded. Links do not fetch anything automatically.

Paired changes and interval endpoints use three decimal places and bracket notation. Percentile intervals are empirical resampling quantiles, not symmetric point-estimate-plus/minus-error intervals. Rank discreteness can make an endpoint equal the observed change exactly. The example audit explains this when its full-precision reconstruction confirms it. A single fixed development example and fixed judge generations do not establish a general causal benefit of adding human examples.

Human agreement is presented at distinct levels: direct rubric direction agreement; rankings from disjoint reviewer groups; full human rankings across student cohorts; and, when supplied, Terra versus a human group using the same questions and independent human reference. The matched diagnostic averages both reference orientations within each reviewer partition. Its percentile ranges measure repeated-partition sensitivity, not confidence intervals from independent studies. The report keeps the support sizes and remaining differences in repeated human votes explicit. An AI-versus-aggregate-human score exceeding human-half agreement alone does not establish AI superiority.

The Judge systems view exposes configurations/members, exact system and user prompts, semantic schemas/transport, and human examples/context. Derived systems reuse member prompts and show their fixed voting shares. Example displays remove author, reviewer, and plan identities, while exact frozen templates remain inspectable. Provider formatting adaptation is distinguished from direct schema compliance: a versioned lossless wrapper/fence conversion must still pass the unchanged semantic validator. Requested versus effective settings and representative saved calls remain linked.

Cost summaries distinguish completed-call attribution, reused panel calls, new inference, router charges, and BYOK upstream inference. Panel costs overlap and are not additive. Recorded or estimated subtotals exclude unresolved charges; they are not guaranteed lower bounds or reconciled invoices. Only execution interruptions with an actual sent signal appear as executed interruptions. Unknown billing and bounds on simultaneous local operations do not become claims about confirmed dispatches or queued jobs. The blocked Qwen follow-up does not claim that its 120 scheduled requests ran.

All charts and behavior use inline SVG and JavaScript, with no CDN, browser dependencies, or network requests. Embedded JSON and displayed source strings are escaped. Large repeated simulation arrays are omitted while full artifacts remain linked. The local HTML contains SSOT-derived results and should be handled alongside those local analysis artifacts.

The original HTML was preserved as `report-before-extension-20260911.html`, and the pre-rewrite report as `report-before-narrative-rewrite-20260911.html`. Focused unit tests cover safe data loading, separate sibling provenance, exact prompts, compaction, missingness, and cohort verification. `results/ranking-study-20260910/report_browser_qa.py` checks the actual local page in headless Chrome: table sorting/reset, every judge and provider selector, prompt/schema access, criterion rankings, missing/unavailable branches, uncertainty captions, and artifact links. Screenshots provide a final visual check of the narrative and tables.

A collapsed execution note records historical 24-worker/eight-per-model admission, the final Flash 24/24 run, current 128/128 defaults and configurable 512/512 limits. The measured Flash median duration is explicitly after admission, includes retries, and excludes local queue waiting. It distinguishes configurable concurrency from achieved throughput and records that Qwen only attempted a blocked preflight. The historical 32,768-token cap is identified as our experiment-budget choice, not a provider requirement.

## First public leaderboard

To put the combined AI-judged leaderboard first, create `report_leaderboard.json` in the study directory with an `evaluation_file` path, for example `{"evaluation_file":"../combined/evaluation.json"}`. The resolved target must be a file within the study directory's parent (the results root); missing, malformed, escaping, or symlink-escaping targets remain pending. The renderer copies only aggregate ranking, coverage, and allowlisted generation and judge settings. A completed, connected, converged fit must name exactly the 12 held-out baseline systems and all explicitly requested systems in both its model list and its rows before global ranks are shown; otherwise model statuses are shown without ranks. The existing validation sections retain their original statistics and selection.

For a standalone aggregate-only report, call `render_public_report(study_dir)`. It writes `public-report.html`, containing the leaderboard and a concise frozen judge-validation summary and methods, without saved student responses, judge prompts, request snapshots, or artifact links. The regular `report.html` retains those detailed validation sections and is intended for local review. Neither renderer makes model calls. Per-rubric fits are independently selected; student bootstrap rank intervals are shown for the overall fit only and condition on connected, converged resamples.
